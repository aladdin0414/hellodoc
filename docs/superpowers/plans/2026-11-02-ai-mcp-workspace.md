# AI 事项空间 MCP 实施计划

**目标：** 复用 HelloDoc 账号、知识库和文档，在不修改数据库结构的前提下，先让 Codex 可以按事项保存 Markdown。

**设计依据：** `docs/superpowers/specs/2026-11-02-ai-mcp-workspace-design.md`。事项空间 ID 位于本机配置；用户和权限沿用现有体系；不添加 MCP 令牌管理及数据库迁移。不同电脑需要分别配置相同的知识库 ID。

**边界：** 不修改已有 REST API 的行为契约；MCP 只处理配置的知识库、事项查询/创建和文档创建；不实现删除、更新、合并事项或生命周期。令牌不进入日志或仓库。

## 1. 基线及兼容性

- [ ] 执行 `cd hellodoc-server && ./gradlew test`，记录已有失败及原因；确认现有文档创建、目录权限、`extra_meta` 合并、文档链接和账号登录/刷新行为。
- [ ] 查阅 MCP 官方 Java SDK 的 Streamable HTTP Servlet、身份上下文传递与客户端版本兼容文档；固定兼容 Java 17 / Spring Boot 3.5 的版本。Codex 首先验证，其他客户端分别记录结果。
- [ ] 为事项字段约定独立的 `extra_meta.hellodoc_ai` 命名空间，现有文件夹只有带事项标记才作为事项；现有文件夹名称、ID 和创建服务继续作为唯一数据来源。

## 2. 事项查询与创建

- [ ] 测试仅返回配置知识库内有标记且用户有权访问的根目录；重命名保持 ID，删除、移出根目录或移出知识库后不可选，恢复后可见；测试现有编辑流程保留元数据。
- [ ] 使用 `DocumentService.getTree` 和 `PermissionChecker` 查询文件夹，返回 ID、当前名称、简介和别名；分页支持遍历全部候选。使用 `DocumentService.create` 创建文件夹，保留审计和索引行为；不复制接口或服务逻辑。
- [ ] 测试同名创建的并发、近义名称，以及用户无编辑权限、跨知识库或目标不是文件夹的情形；并发保护优先使用 PostgreSQL 事务锁和现有字段。不得凭相同名称自动认定语义相同。

## 3. 文档保存和重试

- [ ] 测试创建请求校验事项仍属于指定知识库的根目录，且用户有目标文件夹的编辑权限；直接调用 `DocumentService.create` 保存 Markdown，并保留版本、审计、索引和保存事件。
- [ ] 验证在现有元数据中保存用户、操作类型、请求 ID 和输入摘要，配合 PostgreSQL 事务级锁及事务内查找来保证并发重放幂等；不同输入复用同一 ID 返回冲突。测试同名并发和超时后的结果查询，并明确文档永久删除后的记录不可用边界。
- [ ] 如果无法在不改表结构的情况下满足并发和重试测试，记录复现与权衡，不暗中弱化保证或修改数据库。

## 4. MCP 服务和本地桥接

- [ ] 增加有身份隔离的 MCP Streamable HTTP 端点，提供 `list_items`、`create_item`、`create_document`、`get_operation`；服务端逐请求检查现有身份及权限，不依赖客户端参数作为授权依据。
- [ ] 工具描述明确：先查询候选、明确指定优先、多个合理候选时询问、没有合适候选时新建；超时后使用原请求 ID 查询或重试。模型语义判断可能出错，不能以名称或标识作为唯一依据。
- [ ] 本机 stdio 桥接支持配置服务地址和知识库 ID，复用登录和刷新接口，优先系统凭据库。不能打印密码或令牌；刷新失败时提示重新登录。验证客户端调用期间身份不会串用。
- [ ] 使用真实 MCP 客户端测试协议初始化、工具发现、中文、分页、权限错误和超时；用隔离测试数据进行 Codex 端到端验证。Claude Desktop 桥接与其他客户端分开验证和报告。

## 5. 交付验证

- [ ] 执行后端完整测试和桥接程序测试；核对测试中没有打印凭据、没有数据库迁移文件；确认旧接口未回归。
- [ ] 编写中文配置与登录说明，包括多电脑配置、令牌有效期、HTTP 链路及已验证客户端版本；未验证客户端明确标注。
- [ ] 在隔离实例验证部署与数据库兼容性；不直接修改群晖上的服务或现有数据。
