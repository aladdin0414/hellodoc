# Go 后台重写实施计划

> 执行方式：逐个可验证的业务切片实施；每个切片先建立行为测试，再实现和对照验证。

**目标：** Go 服务完整替代 Java 后台，前端保持不变，既有数据和部署可安全升级。

**架构：** 在迁移分支中保留 Java 作为行为基准，新增独立 Go 服务；使用隔离的数据和外部依赖进行对照测试。所有能力完成后才切换默认部署，最终运行不依赖 Java。

**技术栈：** Go、PostgreSQL、现有 WebSocket/SSE 和客户端协议；具体依赖在相关切片分析后决定。

**设计：** `docs/superpowers/specs/2026-11-25-go-backend-rewrite-design.md`

## 全局约束

- 不改前端；兼容桌面端和 MCP bridge，以及现有 HTTP、WebSocket 和 MCP 行为。
- 保持安全权限、持久化数据、数据库升级历史和文件可用；不在正式服务或正式数据上测试。
- 不以接口数量或模拟响应证明功能完成；差异和未覆盖项必须记录。
- 进行本机服务、数据库或浏览器验证前，先阅读 `.local/test-environment.md`（如存在）。

## 切片及验收

- [ ] **基准与清单：** 盘点 Controller、MCP、WebSocket、定时任务、数据库初始化和迁移、各客户端调用、外部集成；逐项关联源码、现有测试和待补测试。执行安全的现有测试并记录基线和环境限制。
- [ ] **对照测试设施：** 使用互相独立的数据库与文件目录运行 Java 和 Go；相同输入分别执行，比较 HTTP 状态、头、响应和数据副作用；仅对有依据的动态字段做精确归一化。验证差异能被检测、两个目标的数据不能相互污染。
- [ ] **基础服务与系统信息：** 增加独立 Go 模块及运行入口；先为 `GET /api/system/info` 建立行为测试，核对名称、版本、状态、服务器时间格式及权限；再实现并对照 Java。构建版本应与现有 Gradle 版本来源一致，不能把 application.properties 中的开发默认值误当打包版本。
- [ ] **数据库与初始化：** 分别验证空库初始化、初始管理员、既有库启动、Flyway 历史及迁移；Go 不改写既有迁移历史；覆盖失败中断和重复启动。
- [ ] **身份和权限：** 迁移登录、注册、刷新、注销、密码校验、现有令牌及 RBAC；测试未登录、过期/无效令牌、角色变化和跨用户访问。
- [ ] **知识库与文档主链路：** 迁移知识库、成员、文档、目录、收藏、最近访问、权限和分享；覆盖事务、并发写入、冲突和删除恢复。
- [ ] **协作与历史：** 迁移 WebSocket 握手与消息、会话、锁、版本及相关定时清理；对照断线重连、权限和并发写入。
- [ ] **搜索与关联：** 迁移搜索、索引回填、文档关系；以既有 PostgreSQL 数据验证结果和权限过滤。
- [ ] **评论与通知：** 迁移评论、提及、通知和审计日志；覆盖语言、权限和副作用。
- [ ] **附件与存储：** 迁移文件、附件、本地和 S3 配置及清理；验证上传下载、鉴权、现存文件和外部资源获取边界。
- [ ] **AI 和 MCP：** 迁移模型配置、对话、流式生成及 MCP 全部工具、令牌和写入约束；验证 SSE 帧、取消、权限和并发冲突。
- [ ] **系统管理与公开访问：** 迁移用户、角色、权限、字典、配置、公开知识库和剩余接口；按清单逐项核对，包含错误响应和国际化。
- [ ] **部署及切换：** 更新镜像与部署入口并保留既有配置和数据卷迁移路径；验证新装、升级、备份恢复、回滚和重启。只有所有清单项及对应测试通过后切换默认服务并移除 Java 运行依赖。

每个切片开始前依据源码与已捕获行为细化具体接口、数据和测试；完成时记录测试命令、结果、已知差异及未验证项。计划当前是整体路线，不能把未细化的切片视为已实现或已验证。

## 重点检查

1. HTTP 200 携带业务错误码与 HTTP 错误状态都要逐项比较。
2. 原生 fetch、axios 直接调用和 token 刷新不能漏出客户端清单。
3. WebSocket 的查询参数令牌、消息顺序和断线行为需对照。
4. SSE 要检查流帧、取消和连接关闭，而非只检查最终文本。
5. 空库与存量库使用独立数据库测试，验证初始化和迁移历史不会重复执行。
