# HelloDoc AI 事项空间与 MCP 设计

> 优先不修改数据库结构。事项空间 ID 配置在本机桥接程序中，登录复用现有账号体系；事项元数据及去重优先复用现有字段，并发可靠性需经测试验证。

## 目标和范围

让用户在 Codex 等 AI 客户端中要求“总结并保存到 HelloDoc”，由 AI 整理 Markdown、匹配具体事项并保存。事项可以是项目、任务、工作专题或个人计划；同一事项可包含多份文档。首版以 Codex 验证端到端流程，兼容 Claude Desktop、Antigravity、WorkBuddy 和 Hermes 的连接方式需逐一验证。

首版支持通过桥接配置选择知识库作为 AI 事项空间、使用现有账号登录、查找和创建事项以及创建文档。不包含已有文档更新、事项合并、事项生命周期、跨事项关联、自动迁移已有文件夹或云端公开访问。

## 用户体验

1. 用户在本机桥接配置中填写 HelloDoc 地址和事项空间知识库 ID，使用已有账号登录。相同电脑上的客户端可共用桥接配置；其他电脑需分别配置相同 ID。操作时重新校验账号权限。
2. AI 在用户要求保存时整理标题及 Markdown，查询候选事项，比较名称、简介、别名与当前对话。明确指定事项优先；匹配明确则使用已有事项，多个合理候选无法区分时询问用户；没有合适候选时自动创建事项。
3. AI 以事项 ID 创建文档，返回事项名称、文档标题、路径和可打开的链接。保存失败或结果不确定时说明情况，并保留总结供用户重试。
4. 事项不强制设置完成状态。同目标的后续工作可以继续归入；目标明显不同可以新建；模糊时询问。对话里此前选定的事项仅是线索，不能覆盖后续明确切换或明显不同的上下文。

AI 的语义判断不是服务端的确定性保证：不同模型可能判断不同。工具描述应清楚传达匹配、询问和创建规则；通过多客户端实际案例评估效果。一个名称、别名、仓库或客户标识都不是唯一证据。

## 数据和已有能力

### 复用原则

MCP 是现有能力的适配层，优先复用已有接口对应的服务和数据，不另建一套文档存储或以 HTTP 回调本机接口。已有 REST API 的请求与响应保持兼容：

- 选择事项空间时复用知识库列表与既有知识库权限检查；查询事项时复用文档树查询及文件夹数据。
- 创建事项文件夹和 Markdown 文档均复用 `DocumentService.create`，保留既有审计、版本、搜索索引和文档保存事件。现有 `POST /api/kb/{kbId}/documents` 已使用该服务，MCP 不复制其创建逻辑。
- 优先复用文件夹 ID、名称以及现有 JSON 元数据 `extra_meta` 存放事项简介和别名，并采用专用命名空间避免覆盖其他元数据。普通文件夹仅在具有事项标记时视为事项。保存元数据时须合并而非覆盖其他字段；需验证现有编辑、导入导出和移动流程不会丢失该标记。
- MCP 协议适配和本地桥接属于新增能力。幂等记录优先复用现有元数据；若不能可靠满足并发要求，先说明限制和方案，再决定是否调整数据库结构。

现有 `kb_document` 使用父子关系和类型表示目录树，包含稳定 ID、名称、摘要和 JSON 元数据；现有文档创建服务支持指定父目录和内容，并在服务中检查知识库编辑权限。控制器注解不会自动保护直接调用服务的 MCP 入口，因此仍需显式检查配置的知识库范围、目标目录及所需文档权限；不能仅依赖控制器注解或假设服务已覆盖所有边界。

事项元数据优先存放在文件夹现有 JSON 元数据中，保存事项标记、简介和别名；名称以文件夹当前名称为准，避免双份名称漂移。事项 ID 使用文件夹 ID。并发唯一性优先通过现有字段和事务保证，其可靠性需要验证。重命名后 ID 和元数据保留；删除、移出根目录或移出事项空间后不再作为可用事项，也不能继续用于保存。恢复或移回后若元数据仍存在则恢复可见。第一版仅 MCP 创建的事项具备元数据；已有文件夹不自动视为事项，避免意外导入无关目录。

知识库 ID 保存在本机桥接配置，而非数据库；桥接程序不提供跨知识库工具调用，并在每次请求指定该 ID。服务端对每次请求验证账号及目标知识库、目录权限，不能把客户端配置视为服务端的独立安全授权边界。桥接复用现有登录、访问令牌和刷新接口，优先将凭证保存在操作系统凭据库，不写入日志；刷新失败时要求重新登录。账号权限、禁用和令牌失效按现有机制处理。
## MCP 接口和执行

后端提供标准 Streamable HTTP MCP 端点，部署在 HelloDoc 服务中。本机桥接程序使用现有登录方式并指定知识库 ID；为 Codex 提供配置指引，其他客户端分别提供经实测的配置。Claude Desktop 的远程自定义连接器由云端访问，不能直接访问私有地址；为局域网使用评估本地 stdio 桥接，作为兼容工作单独验证，不承诺所有客户端都无需桥接。

工具以稳定 ID 而非名称执行写入：

- `list_items`：在授权空间内分页列出可访问的事项 ID、名称、简介和别名；支持文本过滤，但过滤结果不能当作语义匹配的最终判断。客户端需要能够遍历全部候选。
- `create_item`：接收名称、简介、别名和客户端生成的请求 ID，创建根目录文件夹及元数据。创建时按同一空间内标准化名称检查并发重复；同名时返回已有候选，让 AI 结合描述判断，不能仅凭同名直接归档。近义名称仍可能重复。
- `create_document`：接收事项 ID、标题、Markdown 和请求 ID；验证事项仍属于授权空间的根目录及用户权限后，在该事项下创建文档，返回 ID、路径和链接。
- `get_operation`：按请求 ID 查询创建结果，以便超时后确认。请求 ID 按用户、操作类型隔离；相同 ID 和相同输入返回原结果，不同输入返回冲突。请求标识、输入摘要与创建结果优先保存在现有文档元数据中，并与创建操作在同一事务提交；目标是在记录可用时支持重试查询，删除文档后记录可用性须单独验证。超时后先查结果，未知时用同一请求 ID 重试，不生成新的 ID。

事项创建及文档创建各自原子化；若事项创建成功但文档创建失败，保留事项，并向用户报告实际结果。并发下优先通过数据库事务和现有结构保证同名检查和幂等生效，实际保证须测试验证；近义事项及语义冲突由 AI 与用户处理。操作失败不得报告保存成功。

## 错误和安全边界

明确区分未认证、登录失效、配置无效、权限不足、事项不存在或已移动、名称冲突、参数无效及服务不可用。工具只提供首版所需的查询和创建能力，不提供删除或修改能力。知识库内容属于数据，不作为覆盖工具规则的指令；任何 AI 自动匹配均不能保证完全准确。对话内容发送给 AI 提供方的行为取决于用户选择的客户端和模型。

当前部署是局域网 HTTP。登录凭据和访问令牌可能在该连接上传输；VPN 保护其覆盖的链路，但普通局域网 HTTP 本身不加密，后续可按部署需求配置 HTTPS。不要在文档或示例里写入真实令牌、密码或私人知识库内容。

## 验证与验收

- 验证无需修改数据库结构即可运行；文件夹重命名、删除、移出与恢复后的事项可见性符合约定。
- 测试现有账号登录、令牌刷新和失效、禁用用户、配置的知识库及目录权限变化，确保 MCP 操作不能越权。
- 测试同名并发创建、请求重放、不同输入复用请求 ID、超时查询以及事项创建成功而文档失败的场景。
- 测试 Markdown 原文、中文标题及路径和链接，确认文档在 HelloDoc 中可正常查看；确认现有创建流程需要的索引、版本和事件行为得到保留。
- 用 Codex 端到端覆盖已有事项、新事项、同标识多个候选需要询问、权限不足与失败重试。记录不同模型的误匹配案例；匹配准确率不预设保证。
- 对其余客户端分别记录版本、连接方式、认证能力及实测结果；Claude Desktop 本地桥接单独验证。未完成验证的客户端标记为待验证，不视为已兼容。
