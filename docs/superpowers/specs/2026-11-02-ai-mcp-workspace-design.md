# HelloDoc AI 事项空间与 MCP 设计

## 目标和范围

让用户在 Codex 等 AI 客户端中要求“总结并保存到 HelloDoc”，由 AI 整理 Markdown、匹配具体事项并保存。事项可以是项目、任务、工作专题或个人计划；同一事项可包含多份文档。首版以 Codex 验证端到端流程，兼容 Claude Desktop、Antigravity、WorkBuddy 和 Hermes 的连接方式需逐一验证。

首版支持选定一个知识库作为每个用户的 AI 事项空间、管理 MCP 令牌、查找和创建事项以及创建文档。不包含已有文档更新、事项合并、事项生命周期、跨事项关联、自动迁移已有文件夹或云端公开访问。

## 用户体验

1. 用户在个人 MCP 设置中选择自己有编辑权限的知识库，并创建、复制和撤销 MCP 令牌。一个用户同一时间有一个选定的事项空间；多个令牌和客户端共享它。空间切换后原令牌按新空间生效，操作时重新校验权限。
2. AI 在用户要求保存时整理标题及 Markdown，查询候选事项，比较名称、简介、别名与当前对话。明确指定事项优先；匹配明确则使用已有事项，多个合理候选无法区分时询问用户；没有合适候选时自动创建事项。
3. AI 以事项 ID 创建文档，返回事项名称、文档标题、路径和可打开的链接。保存失败或结果不确定时说明情况，并保留总结供用户重试。
4. 事项不强制设置完成状态。同目标的后续工作可以继续归入；目标明显不同可以新建；模糊时询问。对话里此前选定的事项仅是线索，不能覆盖后续明确切换或明显不同的上下文。

AI 的语义判断不是服务端的确定性保证：不同模型可能判断不同。工具描述应清楚传达匹配、询问和创建规则；通过多客户端实际案例评估效果。一个名称、别名、仓库或客户标识都不是唯一证据。

## 数据和已有能力

现有 `kb_document` 使用父子关系和类型表示目录树，包含稳定 ID、名称、摘要和 JSON 元数据；现有文档创建服务支持指定父目录和内容。现有权限检查分别处理知识库和文档权限。创建接口上的注解不会自动保护直接调用服务的 MCP 入口，必须在 MCP 入口显式进行等价权限检查。

新增事项元数据，以文件夹 ID 为主关联到空间内根目录文件夹，保存简介和别名；名称以文件夹当前名称为准，避免双份名称漂移。事项 ID 使用文件夹 ID。新增受约束的事项表，外键与索引通过 Flyway 管理。重命名后 ID 和元数据保留；删除、移出根目录或移出事项空间后不再作为可用事项，也不能继续用于保存。恢复或移回后若元数据仍存在则恢复可见。第一版仅 MCP 创建的事项具备元数据；已有文件夹不自动视为事项，避免意外导入无关目录。

空间设置按用户保存。令牌绑定用户，不绑定客户端；令牌仅允许 MCP 端点，不能用于普通登录或其他 REST API。令牌生成后只展示一次，数据库只保存安全哈希、标识、所属用户、创建时间及撤销状态；可创建多个令牌分别撤销。每次调用重新检查令牌、用户状态、选定空间及知识库和目标目录的实际权限。无空间、空间失效、用户被禁用或权限不足时拒绝操作并返回可理解的错误。令牌不输出到日志。

## MCP 接口和执行

后端提供标准 Streamable HTTP MCP 端点，部署在 HelloDoc 服务中。为 Codex 提供地址与令牌的配置指引；其他客户端分别提供经实测的配置。Claude Desktop 的远程自定义连接器由云端访问，不能直接访问私有地址；为局域网使用评估本地 stdio 桥接，作为兼容工作单独验证，不承诺所有客户端都无需桥接。

工具以稳定 ID 而非名称执行写入：

- `list_items`：在授权空间内分页列出可访问的事项 ID、名称、简介和别名；支持文本过滤，但过滤结果不能当作语义匹配的最终判断。客户端需要能够遍历全部候选。
- `create_item`：接收名称、简介、别名和客户端生成的请求 ID，创建根目录文件夹及元数据。创建时按同一空间内标准化名称检查并发重复；同名时返回已有候选，让 AI 结合描述判断，不能仅凭同名直接归档。近义名称仍可能重复。
- `create_document`：接收事项 ID、标题、Markdown 和请求 ID；验证事项仍属于授权空间的根目录及用户权限后，在该事项下创建文档，返回 ID、路径和链接。
- `get_operation`：按请求 ID 查询创建结果，以便超时后确认。请求 ID 按用户、操作类型隔离；相同 ID 和相同输入返回原结果，不同输入返回冲突。操作记录与对应创建结果必须在同一事务提交，并保留足以覆盖正常重试的时间，首版为 30 天。超时后先查结果，未知时用同一请求 ID 重试，不生成新的 ID。

事项创建及文档创建各自原子化；若事项创建成功但文档创建失败，保留事项，并向用户报告实际结果。并发下用数据库约束及事务保证同名检查和幂等生效；近义事项及语义冲突由 AI 与用户处理。操作失败不得报告保存成功。

## 错误和安全边界

明确区分未认证、令牌撤销、无空间、权限不足、事项不存在或已移动、名称冲突、参数无效及服务不可用。工具只提供首版所需的查询和创建能力，不提供删除或修改能力。知识库内容属于数据，不作为覆盖工具规则的指令；任何 AI 自动匹配均不能保证完全准确。对话内容发送给 AI 提供方的行为取决于用户选择的客户端和模型。

当前部署是局域网 HTTP。MCP 令牌在该连接上会随请求传输；VPN 保护其覆盖的链路，但普通局域网 HTTP 本身不加密，后续可按部署需求配置 HTTPS。不要在文档或示例里写入真实令牌、密码或私人知识库内容。

## 验证与验收

- 数据迁移可在现有数据库升级；文件夹重命名、删除、移出与恢复后的事项可见性符合约定。
- 测试令牌创建、撤销、禁用用户、空间切换、知识库及目录权限变化，确保不能越权或调用普通 API。
- 测试同名并发创建、请求重放、不同输入复用请求 ID、超时查询以及事项创建成功而文档失败的场景。
- 测试 Markdown 原文、中文标题及路径和链接，确认文档在 HelloDoc 中可正常查看；确认现有创建流程需要的索引、版本和事件行为得到保留。
- 用 Codex 端到端覆盖已有事项、新事项、同标识多个候选需要询问、权限不足与失败重试。记录不同模型的误匹配案例；匹配准确率不预设保证。
- 对其余客户端分别记录版本、连接方式、认证能力及实测结果；Claude Desktop 本地桥接单独验证。未完成验证的客户端标记为待验证，不视为已兼容。
