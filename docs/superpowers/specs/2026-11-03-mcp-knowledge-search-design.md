# MCP 跨知识库检索设计

## 目标与范围

让 AI 根据用户的问题，在当前登录账号可访问的全部 HelloDoc 知识库中查找文档，按需读取正文，综合回答并提供来源链接。检索包含账号有权查看的草稿；不引入向量索引、嵌入模型或新的外部服务。AI 可以从自然语言提取关键词并尝试多个查询，但关键词检索不能保证找到所有语义相关文档。

## 工具与流程

- `search_documents` 接受非空关键词 `query` 和可选 `limit`（默认 20，最大 100），跨知识库搜索；返回文档 ID、标题、知识库 ID 和标题、状态、摘要及文档路径。按相关性排序，并在权限过滤后应用返回数量上限。无结果返回空列表。
- `read_document` 接受文档 ID 和可选字符偏移 `offset`（默认 0），返回标题、知识库信息、状态、路径、正文片段、下一偏移及是否还有内容。每次最多返回 12000 个 Unicode 码点；偏移以 Unicode 码点计，避免拆开代理对。偏移超出正文时返回空片段和结束状态。客户端通过下一偏移继续读取，文档被修改时分页内容可能变化。
- 工具描述引导 AI 用关键词搜索、必要时调整关键词或多次搜索，再读取相关文档；回答时引用来源，证据不足时说明。相对路径由桥接程序结合服务地址构造可访问链接。

## 架构与权限

在现有 MCP 服务端增加只读工具及独立的读取服务，复用现有身份解析、搜索和文档服务。服务端从认证上下文获取用户身份，不信任客户端提供的用户 ID。每个搜索结果和每次正文读取都检查文档 VIEWER 权限，包含草稿；已删除文档不返回。读取时重新检查权限，因此搜索之后权限撤销也不能继续读取。无权访问、已删除和不存在的文档使用统一的不可访问错误，避免泄露存在性。

现有桥接程序的工具白名单增加两个工具。现有写入及事项工具仍限定配置的知识库；两个新工具不注入或受配置的知识库 ID 限制。工具暴露和参数处理按工具区分，避免改变现有写入边界。

## 检索行为

复用现有全局搜索，补充 PostgreSQL 下的中文文本匹配回退，使标题和正文中的中文子串可被检索。全文搜索和回退结果去重，优先保留全文搜索排序；权限过滤必须在最终截取之前执行，不能让无权文档挤掉有权结果。数据库回退和查询实现应避免向客户端暴露无权文档信息。仅匹配关键词，不承诺语义搜索或穷举所有相关内容。

## 错误和边界

空关键词、非法数量、负偏移和无效文档 ID 返回明确的参数错误；认证失效沿用现有认证和桥接重试机制。正文可能为空，正常返回空片段。搜索索引异步更新，刚修改的文档可能存在短暂检索延迟；读取正文以当前保存内容为准。不记录正文、凭证或真实查询内容到日志。

## 验证

测试跨多个知识库的搜索和正文读取、已发布及草稿、中文子串回退、重复结果、限制数量、无权和已删除文档、权限在搜索后撤销、空正文、长文档分页及 Unicode 边界。覆盖服务端 MCP 工具调用与桥接工具发现和参数转发，回归现有写入的知识库范围。更新 MCP 接入文档，说明跨知识库读取范围、配置及关键词搜索限制。
