# HelloDoc MCP 文档更新、检索与保存体验设计

## 目标和范围

让 AI Agent 能安全地跨知识库更新有编辑权限的文档，改善中英文关键词检索的响应速度与结果质量，并清晰地保存和核验 Markdown。按三个可独立交付、验证的工作流实施：安全更新、关键词检索优化、保存体验。保留既有创建和事项工具的知识库范围；更新跨所有账号有权编辑的知识库。PDF 等文件的解析由 Agent 负责，不增加文件上传、OCR、向量模型或语义搜索。

## 1. 读取和安全更新

### 读取契约

`read_document` 对文件返回现有正文、类型和来源字段，新增非负整数 `version` 和 `updatedAt`。对历史空版本统一使用 0；不修改文件夹子项分页行为。文件正文第一页允许不传 `expectedVersion`，返回对应版本；继续读取时必须传第一页的 `expectedVersion`。分页读取时，在同一一致性边界内取得版本和正文；若版本不符，返回 `VERSION_CONFLICT`，要求从头读取，禁止组合不同版本的正文。文件夹的 `offset` 仍是子项偏移，不要求正文版本参数。读取已删除、无权限或加密内容沿用不可访问处理。

### 更新契约

新增 `update_document`，输入 `documentId`、`expectedVersion`、`mode`（`replace` 或 `append`）、`markdown` 和非空 `requestId`（最长 128 字符）。不由调用者指定知识库；服务端按文档所属知识库和当前认证用户校验 `DocRole.EDITOR`。仅允许普通文件，拒绝文件夹、其他类型、加密、已删除或无权限文档。`replace` 的空字符串表示清空正文；`append` 将输入原样拼接，不自动插入换行，空追加作为无效参数。请求内容有界限，沿用现有文档正文大小限制；若现有系统没有统一上限，MCP 限制输入 UTF-8 不超过 2 MiB，并对最终正文使用同一上限。成功返回文档 ID、所属知识库 ID、路径、版本号和更新时间，桥接程序转换为 URL。

`VERSION_CONFLICT` 明确表示正文未被修改；Agent 重新读取后结合用户意图决定是否重试，不自动覆盖。无权限和不存在返回统一不可访问错误。其他参数错误、过大输入、请求 ID 冲突和临时失败分别返回可区分的稳定错误码，不包含凭证或正文。

### 原子性、历史与重试

所有会改变**现有文档正文**的路径（包括普通 HTTP 编辑、协作保存、版本恢复及其他直接调用正文仓库的路径）必须在读取版本或旧正文前进入同一个文档行锁 / 写入协调边界，并在同一事务中写正文与递增版本；实现前逐一审计并列出所有入口，包含内部自调用可能绕过事务代理的情况。新增文件初始化不属于并发更新，但需建立一致的初始版本。历史版本生成、文档版本和正文提交失败时整体回滚。不能只给 MCP 加锁，不能把读取版本与更新放在不同事务中，也不能假设数据库的默认隔离级别会保护分页读取。

新增持久化的 MCP 更新请求记录，以 `(userId, documentId, requestId)` 唯一约束；记录 mode、预期版本和正文输入的哈希、操作状态及结果版本，不存明文正文。第一次请求在同一事务中记录请求和更新结果；相同 ID、相同输入的并发或超时重试返回原成功结果，不再次追加或覆盖；同一 ID 不同输入返回 `REQUEST_ID_CONFLICT`。重试前重新检查当前权限，失权或文档删除不返回内容。请求记录与文档生命周期关联，保留至文档永久删除；迁移和升级兼容旧库。新建工具的既有防重协议不变。

## 2. 关键词检索

保持 `search_documents` 对所有可查看知识库和草稿可用，排除已删除及加密文档；最终结果的权限判断在限制数量之前完成，未授权文档不进入结果、摘要或返回计数。按标题和正文命中分层计分，给标题更高权重，按分数降序、文档 ID 升序稳定排序；兼容中文子串、中英文关键词及大小写。关键词拆分与组合策略必须有明确的测试，不宣称语义理解或必然召回所有相关文档。

先建立可重复的基线：在隔离的 PostgreSQL 测试库中生成不同知识库、权限和文档大小的数据，记录同一批中文和英文查询的耗时及命中 ID。优化候选查询和批量读取，避免为每篇文档逐次读取正文和权限；权限语义以现有 `PermissionChecker` 为准，包含文档级权限、知识库成员、公开和匿名可见规则，不能简单按知识库成员过滤。优先使用 PostgreSQL 可索引的子串候选方案；若采用 `pg_trgm`，必须提供可重复运行的迁移、扩展权限检查和不可用时的正确回退，不允许升级导致现有服务不可启动。全文与子串候选去重后统一排序，再检查权限和截断；分页/批处理必须持续获取候选直到足够或穷尽，不能让无权候选挤掉有权结果。非 PostgreSQL 保留正确的回退路径。

优化完成后在相同测试数据与环境复测，报告基线、优化后耗时、数据规模、查询和命中差异；不预先承诺无依据的毫秒目标。用查询次数和执行计划定位剩余问题，不以本地小样本速度代表生产性能。

## 3. Agent 保存体验

现有 `create_document` 保持接口和防重语义，补充工具说明：用户要求 Markdown 时，应使用可阅读标题、列表、表格及代码块，仅对实际代码使用围栏，不能把整篇转换结果放入代码块。PDF、图片和其他文件由 Agent 解析；无法识别的扫描页、图片或不确定的表格要在文档或回复中标明，不声称 MCP 自动验证转换完整性。保存后按用户意图读取核验；修改已创建的文档时使用 `update_document`，不要重复创建。

创建和更新成功返回 ID、路径及版本；保留现有创建响应字段，向后兼容地增加版本和更新时间。桥接程序为新增工具和文档结果生成同源 URL，同时保留现有事项写入知识库配置的限制；更新不得被桥接程序错误注入固定知识库 ID。更新 `docs/mcp-guide.md`，包含配置范围、并发冲突、幂等重试、分页及 Markdown 示例。

## 验收与测试

- 真实数据库并发测试：两个客户端基于相同版本更新时至多一个成功；MCP 与网页编辑、协作保存、版本恢复交错均不能静默覆盖；失败不留下半写入或孤立历史版本。
- 读取分页测试：跨页期间正文变化返回冲突；Unicode、空正文、初始版本和文件夹分页均保持正确。
- 幂等测试：替换和追加的重复及并发请求只执行一次；同 ID 不同输入冲突；超时后重试、失权后重试、删除后重试不泄露信息。
- 权限测试：跨知识库可编辑文档可更新，仅查看权限、无权、已删除、加密、非文件均拒绝；错误不泄露文档存在性。
- 检索测试：中英文、中文子串、排序、同分稳定、权限、草稿、删除、加密和超过一批无权候选；PostgreSQL 扩展不可用和其他数据库的回退正确。
- MCP HTTP 和 stdio 桥接端到端测试：工具发现、参数、版本冲突、链接与既有创建范围；文档示例覆盖 Markdown 转换限制和保存后核对。
- 执行服务端和桥接完整测试；报告 PostgreSQL 性能基线与优化结果，以及实际环境中未执行的检查。
